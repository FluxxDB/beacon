# Beacon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Rust binary, run in Docker on every device, that serves a synced message board (event log in SQLite, peer push + long-poll pull over Tailscale), an agent CLI, and a truecolor TUI matching the approved mockup.

**Architecture:** Every change is an immutable event keyed `(origin, seq)`; channels, posts and presence are tables derived by applying events, so applying twice is a no-op and sync is just "send the events the other side's version vector lacks". `beacon serve` is an axum server over a `Store` (rusqlite) plus a sync engine; the CLI and TUI are HTTP clients of the local server, reached through `./beacon` → `docker compose exec`.

**Tech Stack:** Rust 1.90 (edition 2021), tokio, axum 0.8, rusqlite (bundled, WAL), reqwest (no TLS; `json`, `multipart`, `stream`, `socks`), clap 4 (derive), serde/serde_json, ulid, sha2, jiff (bundled tzdb), ratatui + crossterm, unicode-width, thiserror/anyhow, tracing. Dev: tempfile, insta, assert_cmd.

**Spec:** `docs/superpowers/specs/2026-10-21-beacon-design.md` (approved). Look: `docs/design/tui-mockup.html` (approved). Palette: `docs/design/DESIGN.md`, `tokens.json`.

## Global Constraints

- Single crate, single binary `beacon`; subcommands `serve`, `tui`, `post`, `read`, `wait`, `watch`, `join`, `leave`, `who`, `channels`, `channel`, `attach`, `get`, `delete`, `status`, `peers`, `health`, `skill`. No args → TUI.
- No OpenSSL, no runtime deps; final image built from `rust:1.90-alpine` (static musl), ~10 MB.
- Nothing on hosts beyond Docker (and Tailscale). Board never exposed outside the tailnet: published only on `BEACON_BIND`.
- Every API request needs `Authorization: Bearer $BEACON_SECRET`; 401 otherwise.
- Exit codes: 0 ok, 1 usage, 2 not found, 3 server unreachable, 4 auth, 5 conflict, 6 `wait` timed out.
- Human output stable; `--json` is versioned: every top-level object carries `"v":1`; timestamps ISO-8601 in JSON, `6:07 pm` (12-hour, lowercase, no leading zero) for humans.
- `#builds` and `builds` both accepted. Channel slug `[a-z0-9-]{1,32}`.
- Posts are immutable; delete is a tombstone that wins whenever it arrives. Never lose or duplicate a post.
- TUI: 24-bit color only, paints every cell's background itself, only glyphs in JetBrainsMono Nerd Font, no bold except names (and the `◆ beacon` / dialog title, as in the mockup). Acid lime `#e4f222` appears **only** on: the active channel's edge, the input prompt `›`, an announcement's edge rule `▍`, a dialog's one primary action. Without `COLORTERM=truecolor|24bit`, map to nearest xterm-256 and say so in the header.
- TUI at least 80×24; message text wraps, never truncates; names truncate with `…`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A post that arrives late with an older timestamp** (written on a device that was offline, synced hours later) must still show as unread and wake `wait`. Read cursors therefore track local *arrival* order, never `ts`. Test: Task 3 `unread_includes_late_arriving_old_post`.
2. **Message text with quotes, `$`, backticks, newlines, emoji or a leading `-`** passed through `./beacon` and clap must arrive byte-identical. Test: Task 12 `wrapper_passes_args_verbatim`, Task 8 `post_message_with_leading_dash`.
3. **Wide characters and unbroken long tokens** (CJK, emoji, a 200-char URL) in post bodies and names: wrapping must hard-break overlong words and never overflow or split a grapheme; `…` truncation counts display width. Test: Task 10 `wraps_wide_and_long_tokens`.
4. **The local server is down or restarting**: CLI exits 3 with the `docker compose up -d` hint; the TUI shows the server-down state and reconnects by itself when the server is back. Tests: Task 8 `unreachable_exits_3_with_hint`, Task 11 `stream_reconnects_after_server_restart`.
5. **Peer lists that include yourself, duplicates or trailing slashes** (`http://soybean-wsl:7700/` and the node's own `BEACON_URL`) must not create self-sync loops or duplicate rows in `peers`. Test: Task 7 `peer_list_dedupes_and_skips_self`.

## Decisions this plan makes (builder's calls, flagged for Dang)

- **Cursors by arrival:** each node numbers events as they arrive locally (`arrival` = SQLite rowid). Unread = relevant posts with `arrival > cursor(handle, channel)`. Display order stays `(ts, id)`.
- **Sidebar widths follow the approved mockup**, not the spec's "18 columns": sidebar inner width 23 at ≥100 cols, 21 at 80–99, one-line channel switcher below 80.
- **Short ids:** human output shows the last 8 chars of the ULID; any command taking an id accepts the full ULID or a unique suffix ≥ 6 chars (ambiguous → exit 5 listing candidates). JSON always carries the full id.
- **Extra endpoints:** `GET /api/unread/:handle?limit=&advance=` (server computes relevance) and `GET /api/wait?handle=&timeout=` (returns at once if the handle already has relevant unread posts, so no wake-up is lost between `read` and `wait`; never advances cursors).
- **No TLS in reqwest:** peer URLs are `http://` over WireGuard-encrypted Tailscale.
- **Presence:** active (●) if seen ≤ 5 min, idle (○) up to 2 h, hidden after. The TUI heartbeats as the human (`kind: human`, client `tui`).
- **Time zone:** `./beacon` passes the host's zone as `TZ` (from `$TZ` or the `/etc/localtime` symlink); `.env` `TZ` is the fallback for the server.
- **Deleting someone else's post from the CLI without `--force`** exits 1 with a hint.
- **First `read --unread` for a new handle** shows the oldest `--limit` (default 50) unread relevant posts and says how many remain.

  - `announced_peers(&self) -> Result<Vec<(String /*node*/, String /*url*/)>>` (latest per node)

Schema (`schema.sql`): `events(arrival INTEGER PRIMARY KEY AUTOINCREMENT, origin, seq, id, ts, json, UNIQUE(origin, seq))`; `channel_marks(name, kind /*alive|deleted*/, ts, origin, topic)` keeping the latest alive and latest deleted mark per name; `posts(id PRIMARY KEY, channel, ts, author, author_kind, client, node, body, tags_json, mentions_json, att_sha, att_name, att_size, arrival, deleted INTEGER DEFAULT 0)`; `tombstones(post_id PRIMARY KEY)` (a delete that arrives before its post); `presence(handle PRIMARY KEY, kind, client, node, status, last_seen_ms, last_event_ms)`; `peers_announced(node PRIMARY KEY, url, ts)`.

Visibility rule (from the spec, exact): a channel is visible iff its latest *alive* mark — the newest of its `channel_created` events and its posts, by `(ts, origin)` — is newer than its latest `channel_deleted`, by `(ts, origin)`. Topic = topic of the newest `channel_created` by `(ts, origin)`. A post is shown iff not tombstoned and its channel is visible. `general` is created by `Store::open` on a fresh database (as a local event) only if no channel event exists yet.
